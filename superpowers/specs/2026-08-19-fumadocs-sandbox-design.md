# react-thaizip Fumadocs migration + sandbox workspace — design spec

Date: 2026-08-19
Status: approved pending written-spec review

## Goal

Migrate the documentation website from Astro Starlight to Fumadocs (Next.js), move
hosting from GitHub Pages to Vercel, and add a gitignored Next.js sandbox app for
exercising the CLI and the scaffolded components against the same package versions
the docs site uses.

The repository keeps two apps side by side:

- `apps/docs` — the Fumadocs documentation website (tracked, deployed to Vercel);
- `apps/sandbox` — a local-only playground (never committed) for testing the real
  `react-thaizip` CLI end to end.

## Prerequisite (already complete)

The folder restructure landed on this branch before this spec:

- `docs/` → `apps/docs/` (Starlight, still building and deploying via `docs.yml`);
- `docs/superpowers/` → `superpowers/` at the repository root;
- `apps/sandbox/` created and gitignored;
- `docs.yml`, `tests/docs-site.test.ts`, `apps/docs/astro.config.mjs`,
  `apps/docs/tsconfig.json`, `.gitignore`, and `CLAUDE.md` updated for the new
  paths.

Verification at restructure time: all 130 vitest tests, `astro check`, and
`astro build` (19 pages) pass.

## Scope

In scope:

- Replace the Starlight site under `apps/docs` with a Fumadocs site, porting all
  existing content and demos as-is;
- Stand up Vercel deployment (root directory `apps/docs`) and remove the GitHub
  Pages workflow;
- Provide a tracked `scripts/sandbox.mjs` generator plus an `npm run sandbox`
  root script that scaffolds `apps/sandbox` from versions pinned in
  `apps/docs/package.json`;
- Rewrite the `tests/docs-site.test.ts` structure guards for the Fumadocs layout;
- Sweep stale links and documentation references (README, CLAUDE.md).

Out of scope:

- Content rewrites or restructuring — the nine existing pages (Thai root +
  English mirror) port verbatim except where the framework forces a change;
- A custom domain (Vercel-assigned URL for now);
- npm workspaces or any change to the root CLI package's build, test, or release
  behavior — the only root change is an added `sandbox` convenience script;
- Core API documentation — the Reference section keeps linking to the `thai-zip`
  site;
- Auto-running the CLI from the sandbox script.

## Decisions

| Topic | Decision |
|---|---|
| Workspace model | Isolated apps: no npm workspaces; root CLI package's build/test/release config untouched (only an added `sandbox` script); each app owns its lockfile |
| Docs framework | Fumadocs (`fumadocs-ui` + `fumadocs-mdx`) on Next.js App Router with Tailwind v4 |
| Locales | Thai root locale at `/docs/...`, English mirror under `/docs/en/...` via fumadocs-mdx root-locale config |
| Hosting | Vercel project with root directory `apps/docs`; `.github/workflows/docs.yml` deleted |
| Demo source | Demos import canonical templates from `templates/react/ts` through the `@` alias; implementations are never copied into the docs app |
| Styling | Fumadocs default theme with minor branding; component design tokens stay in `component-demo.css`; demo presentation CSS migrates from Starlight `--sl-*` variables to Fumadocs variables/Tailwind utilities |
| Search | Fumadocs built-in search (Orama) replaces Starlight's Pagefind |
| Sandbox shape | One Next.js App Router app at `apps/sandbox`, fully gitignored, regenerated on demand |
| Sandbox versioning | `scripts/sandbox.mjs` reads `next`/`react`/`react-dom`/`tailwindcss` versions from `apps/docs/package.json` so the sandbox always matches the docs stack |
| Sandbox CLI usage | Manual: `npm run build` at the root, then `node dist/cli.js init` / `node dist/cli.js add <component>` inside `apps/sandbox` — the script never invokes the CLI |
| Validation | `npm test` structure guards in `ci.yml` (unchanged); full `next build` validation moves to Vercel PR previews |

(already in place from the restructure).

## Content migration

- Move `apps/docs/src/content/docs/**` to `apps/docs/content/docs/**` unchanged —
  frontmatter (`title`, `description`) already satisfies the Fumadocs docs schema.
- Sidebar structure (เริ่มต้น / คอมโพเนนต์ / คู่มือ / อ้างอิง) is expressed with
  `meta.json` files per locale folder: Thai labels in `content/docs/meta.json`,
  English labels in `content/docs/en/meta.json`.
- MDX files import demos via relative paths; those imports keep working once the
  demo components live under `apps/docs/components/`.
- Audit internal links: Starlight slugs (`/getting-started`) become
  `/docs/getting-started` in Fumadocs; every internal `href` in both locales is
  updated accordingly.
- Starlight-specific files are deleted with the migration: `astro.config.mjs`,
  `src/content.config.ts`, `src/content/i18n/th.json`, `src/styles/` layout, and
  the `starlight-links-validator` dependency. Thai chrome strings (search
  placeholder, "Previous/Next") are provided through Fumadocs UI i18n
  configuration on `RootProvider`.
- The `Core API` sidebar entry keeps pointing to
  `https://naay99999.github.io/thai-zip/` (external link, unaffected).

## Demo components

- `AutocompleteDemo.tsx`, `CascadeSelectDemo.tsx`, `FormDemo.tsx`, and
  `demo-shared.tsx` move from `apps/docs/src/components/demos/` to
  `apps/docs/components/demos/` with unchanged logic.
- They continue importing `@/thai-address-autocomplete` and
  `@/thai-address-cascade-select`; the `@` alias resolves to
  `../../templates/react/ts/*` via `tsconfig.json` paths (same technique as the
  current `astro.config.mjs` alias, and the same rule the structure tests
  enforce).
- `component-demo.css` (design tokens for the scaffolded components) is imported
  from `app/global.css`.
- `demos.css` visual rules that reference Starlight CSS variables are rewritten
  against Fumadocs variables or plain Tailwind utilities; the
  `aria-invalid`/`--destructive` visual distinction the tests assert must
  survive the rewrite.

## Sandbox generator

`npm run sandbox` (root `package.json`) runs `node scripts/sandbox.mjs`, which:

1. Reads `apps/docs/package.json` and extracts the resolved version specifiers
   for `next`, `react`, `react-dom`, and `tailwindcss`.
2. If `apps/sandbox` exists and is non-empty, prompts for confirmation before
   wiping it (respect `--force` to skip the prompt; abort otherwise).
3. Writes a minimal Next.js App Router app by hand — `package.json` (pinned to
   the extracted versions), `app/layout.tsx`, `app/page.tsx` (empty playground
   page), `next.config.mjs`, `tsconfig.json`, and `app/global.css` containing
   `@import "tailwindcss";` so the CLI's Tailwind v4 detection succeeds.
4. Writes a `.gitignore` inside the sandbox as a second line of defense.
5. Runs `npm install` inside `apps/sandbox`.
6. Prints next steps: `npm run build` at the repo root, then
   `node dist/cli.js init` and `node dist/cli.js add <component>` inside
   `apps/sandbox`, then `npm run dev` there.

The generator writes files itself instead of shelling out to `create-next-app`
so the scaffold stays deterministic, offline-friendly, and pinned to the docs
stack. The generated sandbox uses the Next.js App Router layout (`app/`
directory) so `detectProjectStructure` resolves to `app/components/` — the most
common real-world target.

## Deployment

- Delete `.github/workflows/docs.yml` after the Vercel project is live.
- Vercel settings: repository `naay99999/react-thai-zip`, root directory
  `apps/docs`, framework preset Next.js (auto-detected). Every push to `main`
  deploys production; every PR gets a preview.
- No `basePath` is needed (Vercel serves the site at its own domain), which
  removes the `/react-thai-zip` prefix from all URLs.
- Old GitHub Pages URLs stop resolving once the Pages deployment is retired;
  README/CLAUDE.md link sweeps cover the references we control. GitHub Pages for
  this repository is disabled by the owner in Settings when the Vercel site is
  confirmed.
- `ci.yml` (CLI) is untouched — it never depended on the docs workflow.

## Testing and verification

- `tests/docs-site.test.ts` is rewritten to guard the Fumadocs layout:
  - the nine slugs exist under `apps/docs/content/docs/` and mirror under
    `apps/docs/content/docs/en/`;
  - `apps/docs/package.json` is private with `dev`/`build` scripts running
    `next`;
  - `apps/docs/tsconfig.json` maps `@/*` to `../../templates/react/ts/*`;
  - demo wrappers import the canonical templates through `@/thai-address-*`
    and `export default` their demo components;
  - no `thai-address-autocomplete.tsx` / `thai-address-cascade-select.tsx`
    implementation copies exist inside `apps/docs`;
  - `.gitignore` covers `apps/sandbox/` and the generated docs directories
    (`node_modules`, `.next`);
  - the forms-guide partial-state documentation assertions carry over verbatim.
- `ci.yml` keeps running these guards via `npm test`.
- The authoritative docs build check is Vercel's PR preview build; the repo does
  not regain a docs build workflow.
- Manual end-to-end verification before closing the migration: `next build`
  passes locally in `apps/docs`, `npm run sandbox` produces a working sandbox,
  and `node dist/cli.js init && node dist/cli.js add autocomplete cascade`
  inside the sandbox yields a running playground at `npm run dev`.

## Migration order

1. Replace the Starlight app with the Fumadocs scaffold inside `apps/docs`
   (content, demos, theme, i18n, aliases) and verify `next build`.
2. Add `scripts/sandbox.mjs` and the root `npm run sandbox` script; run it once
   to confirm the generated app installs and boots.
3. Rewrite `tests/docs-site.test.ts`; run `npm test`.
4. Delete `docs.yml`, update `.gitignore` (`apps/docs/dist/` and
   `apps/docs/.astro/` become `apps/docs/.next/`), sweep README/CLAUDE.md links,
   and retire GitHub Pages after the Vercel site is confirmed live.
