---
title: Data and index
description: Load the bundled dataset, or build an index from your own data
---

Every function takes a `TrigramIndex`. Get one from the bundled dataset, or build it from your own tables. Treat it as opaque; don't construct or mutate one by hand.

## Bundled dataset

`thaizip/data` holds the national dataset: 77 provinces and their districts and sub-districts with postal codes. The data chunk is downloaded only when `loadDefaultIndex()` first runs, in bundlers that split dynamic imports (webpack, Turbopack, Vite).

```ts
import { loadDefaultIndex, getDefaultIndexIfLoaded, clearDefaultIndex } from 'thaizip/data'
```

| Function | Description |
| --- | --- |
| `loadDefaultIndex()` | Returns `Promise<TrigramIndex>`. The first call builds the index (about 40 ms); later and concurrent calls share the same cached index. |
| `getDefaultIndexIfLoaded()` | Returns the index if it is already built, otherwise `null`. Synchronous, so UI can skip a loading state on a warm page. Never starts a load. |
| `clearDefaultIndex()` | Drops the cached index, for example between tests. |

## Your own data

Use `buildThaiAddressIndex` when you have a newer dataset, need only some provinces, or want your own records.

```ts
import { buildThaiAddressIndex } from 'thaizip'

const index = buildThaiAddressIndex(
  { provinces, amphures, tambons },
  { onSkip: (tambon) => console.warn('skipped', tambon.name_th) },
)
```

The tables use snake_case fields, as in the government source data:

```ts
type RawData = {
  provinces: { id: number; name_th: string; name_en: string; geography_id: number; deleted_at: string | null }[]
  amphures: { id: number; name_th: string; name_en: string; province_id: number; deleted_at: string | null }[]
  tambons: { id: number; zip_code: number | string; name_th: string; name_en: string; amphure_id: number; deleted_at: string | null }[]
  geographies?: { id: number; name: string; deleted_at: string | null }[] // unused
}
```

Rows with a non-null `deleted_at` are skipped. A sub-district whose district or province is missing or deleted is skipped too, and passed to `onSkip`.

| Option | Default | Description |
| --- | --- | --- |
| `onSkip` | — | Called for each skipped sub-district. |
| `validate` | `true` | Check field types before building. It costs nothing measurable, so leave it on for data you didn't generate. |

To check data on its own, for example in a build step, call `validateRawData(data)`. It throws a `TypeError` that names the table, row id, field, and actual type, such as `[thaizip] province 12: expected string for name_th, got number`.
